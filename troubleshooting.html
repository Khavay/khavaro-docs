04 / TROUBLESHOOTING

Diagnose before changing code

Many storefront issues are caused by store configuration, missing resources or preview tooling rather than theme code. Use this checklist first.

A section is empty

  • Confirm the section is enabled in the Theme Editor.
  • Check whether it requires a collection, menu, image or other resource.
  • Confirm the referenced resource still exists and contains usable content.
  • Preview the storefront outside the editor as well.

Products are missing

  • Confirm the collection contains products.
  • Confirm products are available to the relevant sales channel and market.
  • Check publication status, inventory and market availability.
  • Confirm the section is assigned to the intended collection.

Navigation is incorrect

Open Shopify's menu management and verify the menu assigned to the relevant theme section. Check every link target and nested item.

Images appear wrong or cropped

Check the selected image, then review image ratio, focal-point and object-fit controls where available. Different source images can require different crops between desktop and mobile.

Cart behavior looks incorrect

Test with a real product and a clean browser session. Verify product availability, variant selection and Shopify cart configuration. If an issue occurs only in a development preview, repeat the test on the storefront URL.

Theme Editor changes do not appear

  • Confirm the changes were saved.
  • Confirm you are viewing the same theme instance you edited.
  • Hard-refresh the browser if an asset appears cached.
  • Check whether the section is hidden on the current template.

Performance concerns

Use Lighthouse on the actual storefront and test the Home, Product and Collection pages on desktop and mobile. Large images, third-party scripts, apps and merchant content can materially affect performance independently of theme code.

When contacting support

Send the store URL, theme version, affected template/page, exact reproduction steps, expected behavior, actual behavior and screenshots or screen recordings when useful. Never send passwords, private access tokens or credentials.
